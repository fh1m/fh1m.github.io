A detector doesn't fire every frame. Underwater, against murk, motion blur and sunlight dancing on the floor, it drops out for stretches, then finds the target again. If the controller only acts when the detector fires, the vehicle stutters, and on a bad stretch it gives up on a target that never left.

So you build a *lock ladder*: a few rungs that keep the target alive through a gap, each less certain than the last, ending in an honest LOST. The question is how long each rung should hold. Six constants guarded Mongla's lock, and every one had been sized from the detection *rate* and from each other. None had been sized from how long a real gap lasts, because nobody had ever measured one.

## Measuring a blink

The ruler is small: pure functions over observations, no ROS, no camera, no model, so a live topic, a recording and an offline replay are all scored the same way. Run over the team's real RoboSub 2025 footage, it found **71 gaps**. One detail decides whether the numbers can be trusted: a gap is measured from the *last sighting*, not the first missing frame, because that's what the control loop compares against. Measuring from the first miss under-reports every gap by a frame, in the direction that flatters you.

## The tracker that emitted nothing

Sizing the ladder surfaced something worse than a wrong constant. The tracker only *starts* a track for detections above a confidence threshold, and the shipped value was 0.6, inherited from pedestrian benchmarks where scores run high. Real underwater scores on the gate approach:

No track, so the coast, the smoother and the lock all had nothing to work with. Nothing raised anything, because a tracker with no tracks still publishes an empty array on time. The fix was structural: the gate is now clamped to the detector's own live threshold, so a detection the detector chose to publish is always allowed to start a track. End to end on the same cached detections, mission-aborting losses longer than a second went from **six to one**, and `/tracks` went from silent to 51.95 Hz.

<Pull>A missed re-acquisition costs a second. A false one costs the run.</Pull>

## The dead zone

The ladder's own code had a quieter defect. An expired Kalman filter could only be revived inside the smoothing call, and the loop skipped that call for expired filters. So once a filter expired while the tracker still held the id, a returning target was suppressed forever. At the shipped settings that was a 70-frame dead zone, on an approach with 53 gaps in 57 seconds.

The test suite couldn't see it, because the one test that could had *reimplemented* the node's loop. It tested a copy, and the copy didn't have the bug. Now the loop is a single function imported by both.

That asymmetry (a lost target is honest, a wrong target is fatal) is why the ladder ends in LOST rather than a confident guess. When identity itself breaks across a gap, that's a different measurement with a different price: [179 identity switches](/notes/179-identity-switches).
