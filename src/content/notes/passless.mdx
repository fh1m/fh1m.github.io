A password is a shared secret: you know it, the server knows a hash of it, and so does whoever breaches the server. Passless is a Python/Flask WebAuthn service that tries the other design. The secret never leaves your device, and the server keeps only a public key.

## What the server actually keeps

After that registration and one sign-in, here's the entire credential row:

| username | public key | length | counter | device type |
|---|---|---:|---:|---|
| fh1m | `pQECAyYgASFYIKmUPLnH29V8…` | 77 bytes (COSE EC2 P-256) | 2 | single_device |

Steal the whole database and you can *verify* signatures. You can't *make* them. The counter is the second line of defence: it rose to 2 on both the authenticator and the server, and a cloned authenticator replaying an old count gets refused.

<Pull>The best secret to protect is the one you never had to store.</Pull>

## The ceremony

1. The browser sends a username. The server sends back a challenge, its relying-party ID, and the credentials it will accept.
2. The authenticator checks you're present (biometric or PIN), then signs the challenge together with the origin and a hash of the relying-party ID.
3. The server checks every piece: challenge, origin, RP ID hash, presence and verification flags, the signature, and that the counter went up.

Each check maps to an attack. The origin check stops a phishing site relaying the ceremony; the RP ID hash stops a credential minted for one site being used at another; the counter catches clones.

It began as a course project, and the report maps each requirement to where it's implemented. 25 tests cover the rejections that matter: an invalid origin, a missing challenge, an unknown credential, and a credential presented for the wrong user. It runs on localhost, self-signed HTTPS, or a Cloudflare tunnel for testing across real phones and laptops.
