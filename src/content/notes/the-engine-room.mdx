The [Mongla](/notes/mongla) note is the tour. This is the engine room: four places where the architecture was measured rather than argued.

## 1 · Control costs vision nothing

The board runs a 500 Hz loop on one ESP32 core: sensors, control, motor commands. The Pi does nothing but see. The split isn't tidiness; it's that a controller must never be late, and a neural net sometimes is.

<Fig src="/media/mongla-docs/cores.webp" alt="The board's timetable: core 1 runs sensors, control and DShot at 500 Hz; core 0 runs MAVLink at 100 Hz, display at 30 Hz, radio and SD at 20 Hz" caption="Two cores that never share a desk. Nothing a human might wait on is allowed onto core 1." wide contain />

The payoff is a reading off the running system: control-loop jitter unchanged under full vision load. When vision spikes, control doesn't.

## 2 · Zero wasted decodes

The Hailo-8 has a scarce budget. So the camera only decodes a frame when the inference worker is idle, and the chip never spends compute on a frame already superseded. The instrumentation says so every ten seconds.

## 3 · Nothing in the hot path holds the lock

Python has one global lock. On a vehicle, a stage that holds it while working freezes everything else. So every stage was audited by *hold × rate*: the fraction of wall time the process is frozen.

Cumulatively that session took the vision pipeline from about 28 ms to 18 ms, removed about 6.5 ms of control-loop poll wait, and took detections from 36.5 Hz to 77 Hz at roughly 30 % less CPU.

## 4 · The sensor is the limit

The goal of optimising a pipeline isn't "fast". It's to make the software vanish as a source of delay, so what's left is the camera.

| | forward | downward |
|---|---:|---:|
| rate | 73.4 Hz | 27.6 Hz |
| pipeline age, median / p99 | 21.86 / 29.58 ms | 46.94 / 52.44 ms |
| frame interval, median | 12.01 ms | 32.01 ms |
| authority at p99 | **1.000** | **1.000** |

Authority 1.000 at p99 means that 99 % of the time, the controller acts on the freshest frame the sensor could possibly have provided. There is no software latency left to remove.
