Pool time is scarce, and a pool can't be reset to the same water twice. A simulated pool costs one terminal and comes back identical every run. So most of an underwater vehicle's life happens in water somebody built. The trick is making sure that water isn't lying.

Mongla Sim is Gazebo Harmonic plus ArduSub software-in-the-loop plus a web operator lab. It gives the autonomy stack the exact MAVLink and camera surface it expects from a real vehicle, without the pool. Thirteen courses, including the SAUVC 2026 final layout, with props from the open sauvc26-world models.

## The contract is a test, not a promise

The simulator and the autonomy stack live in one repository but build as two workspaces, so neither can quietly reach into the other. They're refereed by a single test that reads the simulator's launch files, model description and ArduSub parameters, and fails the moment they stop agreeing with what the autonomy expects.

That test exists because of a real hole in how ROS 2 launch works. Pass a launch argument that a launch file doesn't declare, and nothing happens: no error, no log line, just a configuration nobody reads. A renamed argument fails silently in both directions. So the contract is asserted, not trusted.

| surface | value |
|---|---|
| autonomy MAVLink | UDP 14550 |
| cameras | front and bottom, 640 × 480 |
| DVL (Gazebo's native sensor) | velocity and bottom-track altitude |
| ground truth | its own topic, for scoring |
| operator lab | bound to 127.0.0.1 by default, because its API can arm thrusters |

<Pull>Both failure modes of the vision path are silent. So "it launched cleanly" is never the pass criterion.</Pull>

The README says exactly what to look for before believing vision works: the right model name in the detector log, a *non-empty* class list (a missing class file doesn't crash, it just publishes nothing, forever), and an alignment line that appears when a gate is in frame. That paragraph is the most useful one in the repo, because it names the failure that looks exactly like success.

## Measuring the sim with the sim

`sim_shakedown` is the one-command proof the loop works: arm, hold depth, drive out, drive back, surface, disarm. Two symmetric timed legs and no position feedback, so it's the same file that runs on the real vehicle. Then the residual is measured against ground truth.

  { v: "0.011–0.037 m", l: "of that along-track: symmetric legs retrace almost exactly" },

The structure is the finding: along-track error almost cancels, and cross-track heading drift dominates. That's a fact about timed dead reckoning that a real pool would teach you more expensively.

The simulator also knows its own lies. The pool is 1.6 m deep, so deeper targets bottom out. `surface()` won't confirm in simulation, because the simulated barometer reads 0.33 m at the surface while ArduSub controls on its own estimator. The hull surfaces; the readback never reaches zero. It's written down with the numbers rather than patched over.

The lab exists for the boring reason that most of a vision season is data. Every recorded clip carries its frame counts in a `meta.json`, and the docs include the three-line script that checks frames on disk equal the counts, because the recorder drops writes on a full queue without erroring. An existing directory proves nothing.

<Fig src="/media/mongla-docs/water-murky.webp" alt="The same simulated gate in murky water, barely visible" caption="One turbidity parameter, turned up. The single variable that decides whether a real run scores, so the simulator models it." />

Clean water teaches you the shape of the task. It teaches you nothing about the task. The real water is in [the Mongla note](/notes/mongla).
