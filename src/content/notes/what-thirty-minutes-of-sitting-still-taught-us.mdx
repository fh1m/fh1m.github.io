Underwater, truth is never directly available. That's the whole reason the estimation stack exists. But there's exactly one condition where it is: a vehicle sitting still on a bench, where the true velocity, angular rate and position are known by definition. That measurement had never been taken on this hardware, so it became the first one.

Rest was *verified*, not assumed. If someone had leaned on the desk, |accel| would have said so, and what follows would be desk statistics instead of sensor statistics.

## The headline

<Bars title="gyro: bias against per-sample noise (log)" unit=" °/s" log rows={[
  { label: "worst gyro bias", v: 0.0004, tone: "measured" },
  { label: "per-sample noise floor", v: 0.09, tone: "estimate" },
]} src="Three orders of magnitude apart. Residual yaw drift over the same window: 0.1° per hour." />

Every gyro bias came back under 0.0004 °/s. That has a direct architectural consequence: the board already estimates and removes its own gyro bias before the message ever reaches the Pi, so the localisation filter must *not* try to estimate that bias a second time. Double-correcting a bias that's already near zero only adds noise.

<Pull>The cheapest experiment in robotics is leaving the robot alone and writing everything down.</Pull>

## Allan deviation asks a different question

A standard deviation says how much one sample scatters around the mean. Allan deviation says how *long* you can average the sensor before slow bias drift starts to win over noise reduction. That's the number a filter's process-noise model should be tuned against.
