<Pull by="Bob Ross">We don't make mistakes, just happy accidents.</Pull>

A decision tree takes that literally. Give it enough depth and it will paint a little region around every accident in the data, then present the result as a masterpiece.

In November 2023 my decision-tree script scored **100 %** on the Iris dataset, printed the report and stopped. The README called decision trees "awesome and scary". I was pleased with myself. Of everything in that sentence, *scary* aged best.

<Fig src="/media/notes/happy-little-trees-iris-2023.webp" alt="The 2023 terminal output: accuracy 1.0, every precision and recall 1.00" caption="<b>November 2023.</b> Forty-five test flowers, forty-five right. A perfect score is the scary part." wide />

It also taught me nothing, because Iris is too polite to overfit. So the rewrite gives the tree a canvas with real accidents on it: two interleaved half-moons, a little smudged, with **10 % of the labels flipped on purpose**. No model can honestly beat about 90 % here. Anything above that is memory, not skill.

## Watching it memorise

<Fig src="/media/notes/happy-little-trees-learning_vs_memorising.webp" alt="Training accuracy climbing to 1.0 with depth while test accuracy plateaus around 0.8" caption="Training accuracy climbs to a perfect 1.0. Test accuracy stops caring after depth 2." plot />

| tree | leaves | train | test |
|---|---:|---:|---:|
| depth 1 | 2 | 0.794 | 0.742 |
| depth 2 | 4 | 0.858 | 0.787 |
| depth 8 | 49 | 0.953 | 0.812 |
| unlimited | 72 | **1.000** | 0.783 |
| **pruned (ccp α = 0.0129, chosen by 5-fold CV)** | **4** | 0.858 | **0.787** |

- **Training accuracy is a liar with a perfect score.** The unlimited tree is right about every training point and wrong about one test point in five. The 23 leaves it grows past depth 8 are portraits of individual flipped labels.
- **The test curve barely moves.** After depth 2 it wanders between 0.77 and 0.81 while the leaf count grows eighteenfold. Depth 8 edges ahead on this split, which is exactly the kind of win that disappears with a different seed.
- **The palette knife is the honest tool.** Cost-complexity pruning, its strength picked by cross-validation on training data only, cuts the tree to **4 leaves**. It matches the 72-leaf tree on test, and it's an object a person can read and check.

## The napkin

If a model has to be explained to a robot's safety reviewer, it had better fit on a napkin. So `python -m happytrees.export` writes the pruned tree as a C function: no Python, no NumPy, no model file. It drops straight into an Arduino sketch.

```c
/* 4 leaves, depth 2; generated by happytrees.export */
static inline int predict(const float *x) {
    if (x[1] <= 0.247126482f) {
        if (x[0] <= -0.487924725f) {
            return 0;
        } else {
            return 1;
        }
    } else {
        if (x[0] <= 1.53083217f) {
            return 0;
        } else {
            return 1;
        }
    }
}
```

A test compiles that C with gcc and checks it agrees with scikit-learn on all 600 points, for trees of depth 2, 4 and unlimited.

<Pull>An exporter that's almost right is a bug with good manners.</Pull>

The 2023 script still lives in the repo, scoring its 100 % on Iris, forever pleased with itself. I kept it there as a reminder of what a perfect score feels like from the inside.
